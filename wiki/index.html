Exo internals

An implementation wiki for Exo, an open-source runtime that hosts agents behind an API with durable conversations, sandboxes, credential substitution and network control. It explains how the code works, shows the code that matters, and collects the prompts, ideas and surprises.

What Exo is, in one paragraph

You describe an agent as a markdown file (frontmatter for harness, model and tools; body as instructions). Exo stores it, runs it on a harness of your choice (Codex, Claude Code, Pi, a built-in loop, or your own TypeScript module), and keeps everything the harness does as an append-only event log per thread. Commands run in a sandbox (Firecracker microVM, smolvm, Docker, or a remote provider) whose network goes through an egress proxy that swaps placeholder credentials for real secrets held in a vault, so the model never sees a raw key. Because the log is the source of truth, clients can disconnect, services can restart, and threads can be forked or resumed.

The central design bet

Split a harness into semantics (prompt assembly, model calls, compaction, planning, tool choice) and infrastructure (identity, history, artifacts, secrets, sandboxes). Exo owns only the infrastructure, called the exoharness, and delegates semantics to whichever harness you plug in. The exoharness stores and orders events but never decides what goes in a prompt. The README and exoharness/docs/spec.md state this; the code below shows where the line really falls.

Ten things worth knowing before you dive in

  1. The log is the database. A thread is a directory of UUIDv7-named event objects. The head is derived from the keys, a turn's status is computed from its events, and approvals, wakeups and process-reuse markers are events too. See data model.
  2. Recovery payloads ride along with the start event. TurnWork is written in the same batch as TurnStarted, so any started turn can be resumed from the journal alone. See harnesses and ideas.
  3. Harnesses decide what resumes. Only Codex among the bundled harnesses can resume an interrupted turn; Claude Code and Pi end it as failed. See native harnesses.
  4. The sandbox never sees a real secret. It sees exo_egress_… placeholders; the proxy swaps them in headers only, and only for hosts the secret's policy allows. See egress & vaults.
  5. Secret policy is cryptographically bound. The destination policy is part of the AEAD associated data, so editing the vault file to widen it breaks decryption.
  6. TypeScript harnesses are trusted code on the host. They talk JSONL to a Node child and can call most of the store API. Only the vendor binaries run in the sandbox. See harnesses.
  7. Approvals are events. Any connected client can answer a pending approval, even after a restart, but resuming it mid-tool only works for the Basic harness. See tools & MCP.
  8. One runtime, many shapes. The same Rust runs natively on Tokio, in a CLI process, or compiled to wasm inside a Cloudflare Durable Object using a sans-IO design. See architecture.
  9. There is no compaction prompt. Context is controlled by re-injecting small state each round and by the RLM pattern. See prompts.
  10. Treat the docs as a guide, not a spec. The project says it is under construction, and several documents describe removed or planned features. Surprises has the list.

About this wiki

It was written from a read of the source at commit 58fa2ff (the pre-existing docs were used as input and checked against the code). Source references like crates/exoharness/src/types.rs:296 link to that exact commit on GitHub, so line numbers stay valid as the repo moves. Nothing was built or run to produce it; where a claim rests only on reading code, the page says so. The pages are plain static HTML: open wiki/index.html in a browser, or serve the folder.

Regenerating the search index

Search runs client-side from assets/search-index.js. After editing any page, run node wiki/build-search.mjs to rebuild it. The glossary and file-map tables in reference.html were assembled from per-subsystem notes; edit that page directly from now on.
