Surprises & gotchas

Places where the code does something other than what the docs, the names, or a reasonable first guess suggest. The repo is young and says so ("under construction"), so a good share of these are docs that lag the code or features that are declared but not wired.

Every item here was checked against the source at the commit this wiki was written for. Items marked read, not run come from reading the code; nobody executed them. Tags: docs drift the docs say otherwise, dead path declared or parsed but unreachable, default a default that bites, security relevant to the trust model.

The event log and the queue

The optimistic head check can never fire dead path

ensure_conversation_head compares the freshly loaded record head with the expected_head that every caller derives from that same record (or passes None). There is one call site, and "turn is stale and cannot be resumed" is unreachable. A test named turn_artifact_write_allows_interleaved_conversation_writes confirms interleaving is intended, while the architecture doc still says head tracking is enforced inside the exoharness.

crates/exoharness/src/basic.rs:2459-2466 · crates/exoharness/src/basic.rs:2507-2556 · crates/exoharness/src/basic_tests.rs:1178-1257 · website/docs-src/architecture/data-model.md:46-50

Real write ordering is one process-wide async mutex

BasicExoHarnessInner.write_lock serialises every metadata and event write for all agents and threads, held across the storage PUT. Cross-process exclusion is an OS flock per thread (sessions/<agent>/<thread>.lock).

crates/exoharness/src/basic.rs:199 · crates/exoharness/src/basic.rs:230-232 · crates/exoharness/src/basic/sessions.rs:86-109

Every read lists the whole events/ directory

get_events, load_conversation_record and thread listing call list_keys on the events prefix each time. The cost is O(event objects), and the batch index only helps get_event. Also, storage is files and object_store: sqlx is declared in the workspace manifest but no crate uses it.

crates/exoharness/src/basic.rs:2718-2735 · crates/exoharness/src/basic.rs:2825-2830 · Cargo.toml:66-72

Fork re-mints every event id

A fork is a full copy: it filters by id <= up_to_inclusive in the parent's id space, rewrites id, thread_id and created_at, writes one file per event (batching is lost), copies only bindings/ and artifacts/ (not sandboxes/, title.json or turn_queue.json), and then appends ThreadForked. Parent cursors are meaningless in the child.

Harnesses, recovery and tools

Claude Code, Pi and Cursor fail interrupted turns, though Rust says they can reconcile read, not run

ManagedExecutor::can_suspend_turn is true for every TypeScript kind, and TypeScriptExecutor::can_reconcile_unresolved_tool_call is just config.typescript.is_some(). Credentials, network and sandboxes

Nothing outside tests constructs EgressError::Rejected dead path

The "typed egress rejections" change (#405) adds the variant and a 403 mapping, but both in-tree resolvers push vault errors through ? into Internal, so a local guest still gets a generic 502. It is a hook for hosted resolvers. The PR text calls it EgressRejection; the type is EgressError::Rejected. Policy denials are 502 on the native proxy but 403 in the worker runtime.

crates/exoharness/src/egress_credentials.rs:324-336 · crates/exoharness/src/egress/mod.rs:594-606 · crates/worker-runtime/src/operations.rs:148-158 · egress & vaults

The policy language is small security

No wildcards (*.example.com and IP literals are rejected at load), no method or path rules (they only reach the resolver), and no CIDR in the proxy path (allowed_egress_cidrs is emitted only on the non-proxy Firecracker firewall path). Substitution is header-only: a placeholder in a URL, query or body is forwarded as an inert literal, and deny_unknown_fields rejects a body injection location. A non-443 origin grant is accepted and unit-tested but cannot be used through the sandbox proxy.

Self-improving agent gotchas

"Validate and rebuild" is two cargo builds

The tool description, me.md and SELF-CONTROL say validate, but the only command is restart-all --build: no TS type-check and no tests, so a broken harness.ts is found on the next turn.
